# QFRemote 本机锁 组件包 v2.0.3 · 安装说明

隐私锁的被控端组件。功能口径一句话：**机主手动开开关（默认关、没有自动上锁），开锁当场设一次性密码；锁着时本地黑屏、必须输对密码才能用这台电脑，解锁成功密码当场作废；本地连错 5 次自动重启；远程控制完全不受影响。**

## v2.0.3 变更（2026-10-26）

- 新增**签名信封自更新通道**：调度侧下发 `update` 信封（目标版本＋自家下载地址＋SHA256，全部进 Ed25519 签名域），组件下载后先验 SHA256，再由独立更新进程 `qf-lockupdater.exe` 在服务之外完成替换（备份旧版到安装目录 `backup\`、停服务、换文件、改版号、启服务、验版本），失败自动回滚旧版。只接受严格更高的版本，降级/同版本一律拒绝并留审计。
- 注意：本通道自 2.0.3 起才存在，2.0.2 及更早版本收到 update 信封只会拒绝（`envelope-rejected`），升到 2.0.3 仍需人工跑一次本包的 `install.ps1`；自 2.0.3 起后续版本可全程无人值守下发。
- 锁的规则与行为与 v2.0.2 完全一致。

## v2.0.2 变更（2026-10-25）

- 修复上锁瞬间锁屏窗口偶发「未响应」（Windows 挂起对话框）：锁屏 UI 改为线程钉死＋隐藏建窗＋进消息循环后分步初始化（捕获排除逐屏做、全部就绪才显示），与服务的管道通信改为带硬超时的异步单飞客户端，界面线程不再被任何初始化或网络等待堵住。
- 锁的规则与亮灭行为与 v2.0.1 完全一致，本版只修稳定性。

## 锁屏时屏幕怎么亮灭（v2.0.1 新增）

- 上锁后本地屏幕自动全黑，密码框是收起的。
- 只有人在电脑跟前动实体键盘/鼠标，屏幕才亮起来、露出密码框。
- 亮起来后 60 秒没人再动，自动重新全黑；再动再亮，如此循环。
- 远程操作不会让本地屏幕亮：远程送来的键鼠动作全程不算数，远程用得再久，本地也一直全黑、密码框不弹。系统通知、其他程序弹窗同样亮不了屏。
- 输对密码解锁或远程关锁后，屏幕恢复正常显示。

## 包内容

| 文件 | 用途 |
|---|---|
| `app/QFLockService.exe` | 系统服务（状态机、计数、看门狗、信封处理） |
| `app/QFLockUI.exe` | 会话 UI（黑屏＋密码框，由服务按会话拉起，不用手动运行） |
| `app/qf-lockctl.exe` | 命令桥（生产只用 `apply` / `status` 两个动作） |
| `app/qf-lockupdater.exe` | 独立更新进程（由服务在收到 update 信封时拉起，不用手动运行） |
| `install.ps1` | 安装/升级（管理员） |
| `install-upgrade.ps1` | 无人值守升级脚本（由 qf-lockupdater 调用，含备份与失败回滚，不用手动运行） |
| `uninstall.ps1` | 卸载（管理员，带留痕） |
| `install-manifest.template.json` | 安装清单字段说明 |

## 安装（本机）

管理员 PowerShell 里：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 `
  -Owner "机主的QFRemote账号" `
  -NodeId "node//……" `
  -ServerHost "服务器地址" -ServerPort 8443 `
  -DispatcherPubKeyFile ".\dispatcher-pubkey.txt"
```

- `-Owner` 必填且必须是这台机器登记机主的账号——找回密码时验的就是它，填错等于把找回链锁死（只能走人工审核）。
- `dispatcher-pubkey.txt` 由站长用 `qflock-dispatch keygen` 生成（公钥部分）。没有它，远程上锁/重设/关锁的信封一律被拒，本机功能不受影响。
- 装完脚本会打印服务状态与 `qf-lockctl status` 的输出，看到 `"state": "Off"` 即正常待命。

## 静默部署（经 MeshCentral，机主无感）

1. 把组件包 zip 传到目标机任意目录并解压（MeshCentral 文件通道）。
2. RunCommand（PowerShell）执行上面的 `install.ps1` 命令行（参数按该机填）。
3. 用 MeshCtrl Download 取回 `%ProgramData%\QFRemote\Lock\status.json` 核对 `state`、`ownerUsername`、`devicePublicKey` 已就位。

## 升级

- **2.0.3 起可远程无人值守升级**：调度侧发 `update` 信封即可，组件自下载、自替换、自回滚，结果看 `status.json` 的 `version` 字段。
- 人工升级：新包解压后重跑 `install.ps1`（同参数）。服务会停→换程序→重启；**状态、审计、设备密钥都在数据目录，不受影响**，锁着升级完还是锁着。

## 卸载

管理员运行 `uninstall.ps1`。默认保留 `%ProgramData%\QFRemote\Lock\`（内含审计记录）；确认不要留痕再加 `-PurgeData` 连数据删除。卸载动作本身会先写入一条审计并打印 `QFLOCK-UNINSTALLED` 标记行。

## 日常操作在哪

- 上锁/关锁/远程重设：站长或机主用 `qflock-dispatch make` 生成信封，经 MeshCentral 投递（命令由工具打印）。软件三端的开关按钮走同一条通路。
- 本地解锁：锁屏上输本次密码；忘了走锁屏上的「忘记本次密码」（输 QFRemote 登录密码验密重设）；登录密码也忘了 → 找站长人工审核，没有第三条路。
- 查状态：`qf-lockctl status`（本机）或取回 `status.json`（远程）。

## 边界（说清不吹）

- 防的是围观和电脑旁的普通使用者。防不住：本机管理员强杀/卸载（会留痕）、安全模式/U盘启动/拆硬盘、Ctrl+Alt+Del 安全屏（任何程序都拦不住；按下后看到的是 Windows 安全屏，桌面内容不泄露）。
- 账号若在 QFRemote 开了两步验证，锁屏上的登录密码找回走不通（验密通道不支持两步验证令牌），用人工审核。
- 黑屏不挡远端的关键一步（捕获排除）必须在真机上按验收清单实测，见交付报告的「真机验证门」清单。
